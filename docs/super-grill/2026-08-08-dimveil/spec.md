# 暗幕（Dim Veil）功能规格

## 1. 目标

“暗幕”是一个离线、无广告、无追踪的原生 Android 工具。它通过触摸穿透的纯黑半透明覆盖层，使视觉亮度低于设备系统亮度滑杆可达到的最低效果。

应用显示名为“暗幕”，Android 包名为 `com.h166278.dimveil`。项目以 GPL-3.0 在公开仓库 `h166278/dimveil` 发布。

## 2. 范围与非目标

### 本版范围

- 简体中文 Compose 主界面：主开关、4 个模式、遮罩深度滑杆、覆盖状态与无障碍状态入口。
- 黑色遮罩，深度范围 0%–90%。Android 12+ 普通悬浮窗为保证触摸穿透最多应用系统允许的遮挡透明度（通常 80%）；81%–90% 由用户启用的可信无障碍覆盖承担。
- 普通应用悬浮窗覆盖层作为默认路径。
- 用户主动启用的无障碍覆盖层作为增强覆盖路径。
- 运行时前台服务与可选通知关闭操作。
- 持久化模式、深度与自定义深度；应用或设备重启时不自动打开遮罩。
- 原创“光能守卫 / 暗影守卫”状态视觉和原创“暗幕能量核心”桌面图标。

### 明确不做

- 不修改 Android 系统亮度，不申请 `WRITE_SETTINGS`。
- 不联网，不包含广告、统计、崩溃上报、账号、云同步或远程配置。
- 不读取屏幕内容，不执行自动点击，不控制其他应用，不监听输入。
- 不使用参考角色图片、角色名称、官方标志或可识别复刻形象。
- 不实现定时、按应用生效、边缘闪光、自动点击、视力测试或悬浮球。
- 不承诺在所有 OEM/Android 版本上覆盖状态栏或导航栏。

## 3. 用户界面与状态

### 主界面

采用深色“暗幕”视觉：原创能量核心图标、中央圆形开关、模式卡片、遮罩深度滑杆、覆盖方式状态卡。左上为应用品牌与状态头像，右上仅显示无障碍状态图标。

遮罩关闭时显示原创“光能守卫”图标；遮罩开启时显示原创“暗影守卫”图标。它们只表示本应用状态，不引用或模仿现有角色 IP。

### 主开关

- 关闭状态点击：若可用覆盖权限存在，启动覆盖；否则仅此时引导至悬浮窗系统设置。
- 开启状态点击：立即移除覆盖并停止运行服务。
- 无障碍已启用时优先使用无障碍覆盖；未启用时使用普通悬浮窗覆盖。

### 模式与深度

| 模式 | 默认深度 |
| --- | ---: |
| 夜间 | 62% |
| 阅读 | 42% |
| 游戏 | 28% |
| 自定义 | 首次 50%，以后保存该模式最后手动设置值 |

选中预设时立即设置相应深度；拖动滑杆将当前模式的深度保存。显示值必须为 0–90 的整数百分比。达到 80% 或以上时，界面显示“深度较高，请确认仍能看清屏幕”。

### 无障碍状态图标

- 未启用：右上显示黄色、低干扰警告图标；点击后显示说明和“去开启”，再跳转 Android 无障碍设置页。
- 已启用：右上显示绿色、低干扰状态图标；点击后仅显示“无障碍全屏覆盖已开启”状态菜单及系统设置入口，不关闭遮罩。
- 每次页面进入前台时静默刷新图标；绝不自动弹窗或跳转。

无障碍服务名称为“暗幕全屏覆盖服务”。系统和应用内说明固定为：`仅用于在屏幕上显示护眼遮罩，不读取屏幕内容、不执行点击、不控制其他应用。`

## 4. 覆盖与服务设计

### 纯黑遮罩

覆盖 View 使用纯黑色，透明度由深度百分比映射。它不改变色温和系统亮度。窗口必须是非焦点、非触摸模式，保证点击、滑动与输入继续传递给下方应用。

### 普通覆盖

普通路径要求用户授权 `SYSTEM_ALERT_WINDOW`。缺失时不得创建覆盖；用户可取消系统设置，返回后仍留在主界面。

### 无障碍增强覆盖

当用户手动启用本服务时，使用 `TYPE_ACCESSIBILITY_OVERLAY`。服务不声明或调用窗口内容读取、节点遍历、手势注入、自动点击或输入监听能力。服务断开时，覆盖路径退回普通悬浮窗（若其权限仍可用）或关闭。

### 前台服务与生命周期

覆盖开启时启动前台服务；服务维护覆盖层和运行状态。通知权限存在时，通知显示：

- 标题：`暗幕正在运行`
- 内容：`遮罩深度 {N}% · {模式名}`
- 操作：`关闭遮罩`
- 点击通知正文：打开主界面。

Android 13+ 用户拒绝通知权限时，仍允许覆盖运行，但主界面提示“通知权限未开启，无法使用通知栏关闭按钮”。

从最近任务划掉应用时，服务的 `onTaskRemoved()` 必须立刻移除覆盖、关闭通知并停止自身。设备重启不恢复覆盖。下次打开应用读取模式和深度，但默认关闭。

## 5. 数据与权限

DataStore 仅保存本机偏好：当前模式、各模式深度及最后保存的自定义深度。不得保存用户账号、屏幕内容、使用数据、设备标识或网络数据。

预期权限：

- `SYSTEM_ALERT_WINDOW`：用户可选的普通覆盖。
- 无障碍服务绑定权限：仅由系统设置在用户明确启用后授予。
- `FOREGROUND_SERVICE`：覆盖运行期间维持服务。
- Android 13+ `POST_NOTIFICATIONS`：仅用于通知关闭快捷操作，可拒绝。

## 6. 技术架构

- Kotlin + Jetpack Compose + Material 3。
- Android minSdk 26，targetSdk 35。
- `MainActivity`：Compose 界面与系统设置跳转。
- `MainViewModel`：协调 UI 状态、DataStore 偏好和服务命令。
- `OverlayService`：普通悬浮窗、前台通知、任务移除清理。
- `DimAccessibilityService`：仅用于无障碍覆盖层渲染与状态报告。
- `OverlayController`：根据首选路径创建、更新、移除唯一的黑色触摸穿透层。
- `DimPreferences`：DataStore 持久化接口。

数据流：`Compose UI → MainViewModel / DimPreferences → OverlayService → OverlayController → normal or accessibility overlay`。

## 7. 失败与恢复

| 条件 | 用户可见结果 | 恢复方式 |
| --- | --- | --- |
| 未授予悬浮窗且无无障碍 | 点击开启时显示权限引导 | 用户从系统设置返回后再次点击开启 |
| 无障碍未启用 | 黄色右上图标；普通覆盖仍可用 | 用户主动开启后使用增强覆盖 |
| 无障碍服务断开 | 尝试普通覆盖，否则关闭 | 返回主界面重新开启或重授权限 |
| 通知权限被拒绝 | 无通知关闭按钮，主界面有提示 | 在系统设置允许通知或从主界面关闭 |
| 从最近任务移除 | 遮罩、通知、服务立即消失 | 重新打开应用并手动开启 |
| 设备重启 | 遮罩保持关闭 | 打开应用并手动开启 |

## 8. 验收与构建

GitHub Actions 是唯一默认构建与验证路线。工作流在 GitHub 托管 Ubuntu Runner 上执行 Gradle debug APK 构建和单元测试，上传 APK Artifact。

验收至少包括：

1. Android 8/API 26 与 Android 15/API 35 编译目标兼容配置正确。
2. 0%、28%、42%、50%、62%、90% 遮罩强度正确映射为黑色覆盖。
3. 覆盖 View 不拦截触摸。
4. 预设值、滑杆值和自定义值在应用重启后保留；运行开关不保留。
5. 缺失悬浮窗权限仅在用户点击开启时提示。
6. 无障碍状态仅在右上显示，前台刷新不弹窗。
7. 通知关闭操作、`onTaskRemoved()` 与服务停止均移除覆盖。
8. APK 和源码不包含角色参考图、角色名称或网络 SDK。

## 9. 已知限制

Android 与 OEM 的系统窗口策略会影响普通悬浮窗覆盖到状态栏、导航栏的程度。无障碍增强路径也需用户主动启用，且不同厂商的省电策略可能停止服务；本应用必须正确清理遮罩，不能承诺绕过系统策略。
